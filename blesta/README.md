# Xtream UI Pro - Blesta module

Sells IPTV lines and sub-reseller accounts from Blesta. Each Blesta service is one line (or one
sub-reseller account) in your Xtream UI Pro panel, created and managed through the panel's Reseller API.

> **Not tested inside a licensed Blesta.** Blesta is commercial software and needs a licence, so
> this module has never run in a real Blesta installation. It was written from the Blesta developer
> documentation (docs.blesta.com) and the open-source `blesta/module-*` modules, every PHP and `.pdt`
> file passes `php -l`, and its code paths (module row, package fields, add / suspend / unsuspend /
> renew / cancel, client and admin views) were run for real against a panel API with a stand-in for
> the Blesta classes (`plugins/e2e/blesta-harness.php`). Expect to try it on a Blesta test
> installation first; what the stand-in cannot show is how Blesta itself calls the module (order
> forms, invoice and renewal timing, page layout).

## Requirements

- Blesta 5.x or newer (the views use the Bootstrap 5 markup of Blesta 5/6), PHP 7.4 or newer with the
  `curl` and `json` extensions.
- An Xtream UI Pro panel whose API address (`cmd/api`, for example `https://api.example.com`) is
  reachable from the Blesta server. Use a valid TLS certificate: certificates are always verified.
- A **reseller** account in the panel with enough credits. Creating and renewing is charged to this
  reseller's credits.

## Install

1. Upload the `components/` folder of this package into your Blesta root, so that you get
   `<blesta>/components/modules/xtreampro/xtreampro.php`.
2. In Blesta go to **Settings > Company > Modules > Available**, find **Xtream UI Pro** and click
   **Install**. No Composer and no database step.

## Get the API key

1. Sign in to the panel as the reseller account that will own the lines.
2. Open `/api-key` in the dashboard and generate (or copy) the API key.
3. Only reseller accounts work. Admin keys are refused with `FORBIDDEN`.

## Add the panel (module row)

1. **Settings > Company > Modules > Xtream UI Pro > Add panel**.
2. **Name**: anything. **Host name**: the panel's API host, for example `api.example.com` (no
   `http://`, no path). **Port**: only when it is not 80 / 443. Tick **Use SSL** when the API is
   served over https (recommended).
3. **API key**: the reseller's key. Blesta stores it encrypted; the edit page never shows it, and an
   empty field keeps the stored key.
4. Saving runs a connection test (`user_info`); a wrong host or key is refused with a readable message.
5. Optionally add a panel group if you want several panels behind one package.

## Set up a package (product)

**Packages > Add Package**, module **Xtream UI Pro**, pick the panel (or group). The package fields:

| Field | Applies to | Meaning |
| --- | --- | --- |
| Service type | both | **IPTV line** or **Sub-reseller account**. |
| Panel package | line | The panel's package, loaded live from the panel (`id => name (credits, duration)`). Packages the panel says are for MAG / Enigma boxes only (`sells` without `line`) are not listed. Save a panel first so the list can load. |
| Trial line | line | Create the line as a trial. |
| Delete permanently on cancel | both | Unticked (**default**): the line / account is only disabled when the service is canceled and can be enabled again. Ticked: it is **deleted on the panel** - final, nothing can be brought back (a returning customer gets a new line). |
| Credits on creation | sub-reseller | Whole number, 0 or more, handed to the new account. The reseller also pays the group price of the account. |
| Credits per renewal | sub-reseller | Whole number, 0 or more, handed to the account at every renewal (0 = a renewal does nothing on the panel). |

When ordering, the customer (or an admin) may enter a username and password; blank values are
generated by the module (random, from a CSPRNG). The panel may ignore custom credentials (reseller
group setting), so the module always stores the username and password the panel actually used.
Sub-reseller usernames are 3 to 32 letters, digits, `.`, `_` or `-`; the account gets the Blesta
client's email, first and last name. The email must be unique on the panel.

Service fields stored by the module: `xtreampro_username`, `xtreampro_password` (encrypted),
`xtreampro_panel_id` (line id or account UUID), `xtreampro_nonce` and `xtreampro_generation`.
Email tags: `{xtreampro_username}`, `{xtreampro_password}`, `{service_type}`, `{package_id}`,
`{host_name}`, `{port}`.

## What each action does

| Blesta action | Panel call | Notes |
| --- | --- | --- |
| Add service | `pricing`, then `create_line`, or `create_user` then `adjust_credits` | Charged. `pricing` runs first: too few credits or a package that cannot be sold as a line fail at once with the amounts and nothing is created. `request_id = blesta-create-<nonce>-<generation>` (sub-reseller: `blesta-sub-…` and `blesta-subc-…`), so a repeated request for the same service never charges twice and a service created after a cancellation sells a new line. With "use module" off the service is only recorded in Blesta. |
| Suspend | `disable_line` / `disable_user` | Free. |
| Unsuspend | `enable_line` / `enable_user` | Free. |
| Cancel | `delete_line` / `delete_user`, or the `disable_*` call | Depends on **Delete on cancel**. A line already gone from the panel counts as done. After a deletion the panel id is cleared and the generation goes up. |
| Change package (admin / client upgrade) | `get_line`, `pricing`, `package_compatibility`, then `change_package` | **Charged** (the new package's official price). Lines only. The module log gets the panel's answer to `package_compatibility` (time left kept or lost, price); too few credits refuse the change. A panel that answers `UNKNOWN_ACTION` skips the check. `request_id = blesta-chg-<nonce>-<package>-<expiry now>`. |
| Renew | `pricing`, then line: `renew_line`; sub-reseller: `adjust_credits` | **Charged.** Blesta calls it when a renewal is paid. A line is extended by the package's official duration; a sub-reseller gets **Credits per renewal**. `request_id = blesta-renew-<serviceid>-<renewal date>` (`blesta-subr-…`): a retry of the same renewal is not charged twice, the next renewal period is. |
| Edit service (admin) | `edit_line` / `edit_user` | Password only. For lines the stored password is read back, because the group may refuse a change. |

The **service page** (admin and client) shows username, password, status, and expiry (lines) or
credit balance (sub-reseller), fetched live. The client tab **IPTV details** adds, for lines, the
server URL, M3U playlists, XMLTV guide, player API and web player links exactly as the panel returns
them (`get_line` links); for sub-resellers, status and credit balance only.

Renewals cost credits: keep the reseller's balance topped up, otherwise renewals fail with "The
reseller account has not enough credits" and Blesta shows the error on the service.

If handing over the credits fails after a sub-reseller account was created (for example not enough
credits for price plus top-up), the order is refused with a message that names the account: give the
credits on the panel and do not repeat the order, a repeat would create a second account.

## Logging and security

- Module calls are visible under **Tools > Logs > Module** in Blesta. The API key is never logged
  and line passwords are masked (also inside `password=` of play links).
- TLS verification is always on, 5 s connect / 20 s total timeouts, redirects are never followed.
- All output in the views is escaped with `Html::safe`.

## Not included

- A receiver for the panel's webhooks: Blesta gives a module no HTTP endpoint of its own, so there is nothing to
  register a webhook against. Use the panel's API key page to watch events elsewhere (or the webhook bridge).
- Changing a line's username after it exists.
- The module does not top up the reseller's own credits.
- No panel-side password reset for the customer: the admin changes it in the service edit form.

## Troubleshooting

| Code | Meaning | What to do |
| --- | --- | --- |
| `INVALID_API_KEY` (401) | Key unknown or revoked | Re-enter the key in the panel's module settings. |
| `FORBIDDEN` (403) | Not a reseller account, missing permission, or (sub-resellers) the group may not create / delete sub-resellers | Use a reseller account; check its group permissions. |
| `RESOURCE_NOT_FOUND` (404) | Line or sub-reseller not in the panel | It was deleted in the panel; cancel the service. |
| `INVALID_REQUEST` (400) | e.g. username / password shorter than the group's minimum, invalid email | Adjust the credentials or the group setting. |
| `INVALID_PACKAGE` (400) | Package missing, not allowed, or for MAG / Enigma boxes only | Re-select the panel package on the Blesta package. |
| `REQUEST_ID_SPENT` (409) | The line this order's request id paid for was deleted on the panel, so the same id cannot sell another | Cancel the service and order a new one. |
| `INSUFFICIENT_CREDITS` (402) | Reseller balance too low | Add credits in the panel, then retry. |
| `CONFLICT` (409) | Username (or, for sub-resellers, email) taken | Choose another. |
| `RATE_LIMITED` (429) | Too many requests | Wait and retry. |
| `UNKNOWN_ACTION` (400) | Panel too old for this module | Update the panel. |
| `SERVER_ERROR` (500) | Internal panel error | Check the panel logs. |
| Could not connect | Network, port, TLS | Check host name, port, the SSL box and the certificate. |

## Verified / guess (1.1.0)

Run for real against a panel, with the stand-in for Blesta (`plugins/e2e/blesta-harness.php`):

- `X-Connector` (read back from the panel's API call log), `pricing` before a sale / renewal, `sells` filtering
  of the package list and refusal of a box-only package, `change_package` through `changeServicePackage` with
  the charge and the repeat guard, `REQUEST_ID_SPENT` after the line was deleted on the panel, the default of
  **Delete permanently on cancel**.

Still a guess (needs a licensed Blesta):

- That Blesta calls `changeServicePackage($package_from, $package_to, $service, ...)` with exactly these
  arguments when the package of a service is changed, and what it does with the return value (the module
  returns `null`, like Blesta's own modules). The older code paths of 1.0.0 have the same caveat as before.
- The insufficient-credits refusal of a line sale was not run (it would need a run that empties the reseller's balance); the
  refusal of a package that is not sellable, which goes through the same `pricing` check, was.

## Running the stand-in test

```sh
API_KEY=<reseller key> API_PORT_NUM=<panel port> MODULE_DIR=plugins/blesta/components/modules/xtreampro \
  php plugins/e2e/blesta-harness.php
```

It loads the real module, views and API client with a minimal stand-in for the Blesta classes
(`Module`, `Input`, `Loader`, `Language`, `ModuleFields`, `View`) and checks the panel's state after
each step. See `plugins/e2e/README.md`.
